# Shelf Life — Changelog

Everything that's shipped, roughly in the order it was built. See `ROADMAP.md` for what's still to do.

- **Comics support** — track comic books alongside games in the same collection: series, issue number, publisher, writer/artist, CGC-style grade, variant covers.
- **Rebrand to Shelf Life** — new name across the app.
- **Currency selection** — pick a display currency in Profile Settings instead of being locked to USD (display only, no live conversion between currencies).
- **Avatar upload** — upload a photo directly (via Supabase Storage) instead of only pasting an image URL.
- **Per-type stats** — dashboard stats bar shows a Games/Comics split.
- **Find Collectors search page** — search public profiles by username/display name, with a default "recently joined" list.
- **Cover images fit the frame** — switched from cropping covers to fill the box to showing the whole image, letterboxed if needed.
- **Edit profile shortcut** — your own profile page now has an "Edit profile" button that jumps straight to Profile Settings.
- **Trophies** — a PlayStation Trophies-style achievement system: bronze/silver/gold/platinum badges for collection milestones (first item, 10/100 items, 25 completed, follower counts, variant hunting, etc.), shown as a trophy case on public profiles. Awarded server-side so they can't be gamed.
- **Mobile layout pass** — smaller card grid, scaled-down type, and a decluttered card layout on phones so nothing feels oversized or cramped.
- **Top Trumps-style card redesign** — full-bleed cover art, a color nameplate pulled from the art itself, and a grading-slab-style stat block instead of loose badges.
- **More collectible types** — Trading Cards, Vinyl Records, Books, DVDs, and CDs added alongside Games and Comics (seven types total), each fully separate with their own tailored fields.
- **Home page redesign** — split hero with a card showcase, alternating value-prop rows built from the app's real trophy/leaderboard styling instead of generic template blocks.
- **Switched game auto-fill from RAWG to IGDB** — RAWG had become unreliable (widely reported as unmaintained, frequent downtime). Auto-fill now runs through IGDB via a server-side route that keeps the Twitch client secret private.
- **Barcode scanning via phone camera** — a "Scan" button next to the Barcode/UPC field opens the camera, reads the barcode, and looks it up to auto-fill title/cover (and author/artist/publisher where available): Open Library for books, a general UPC database for everything else. Works on Safari/iOS as well as Android/desktop. Coverage isn't universal — not every barcode is in either database, especially for older or niche items — and the free UPC lookup is capped at 100 lookups/day site-wide.
- **Duplicate/copy an item** — a "Duplicate" button when editing an item opens a new Add form pre-filled with everything except the barcode, so adding a similar item (another card from the same set, another platform's copy of a game) doesn't mean retyping every field.
- **Trading card search** — for trading cards, a Search button next to Title looks up the typed name on free Pokémon TCG and Magic: The Gathering databases to auto-fill set, card number, cover art, and publisher. (A camera-based "Scan Card" version using on-device OCR was tried and pulled back out — reading card names off photos was unreliable enough to be more frustrating than useful. Typing the title and hitting Search works well instead.)
- **Autocomplete from your own collection** — fields like Publisher, Artist, Genre, Card Set, and Platforms now suggest values you've already typed before, pulled from your existing items. The more you add, the more it starts filling itself in — no typing "Marvel" or "Nintendo Switch" from scratch every time.
- **Community suggestions while adding an item** — as you type a title, if anyone else has already added a matching item (or you have, previously), it shows up in a "already in the community" list — click it and it fills in cover, platform, publisher, and the rest from their entry instead of typing it all out. Only ever pulls from your own items or from public profiles, using the same privacy rule that already keeps private collections out of the leaderboard.
- **Browse by system on the dashboard** — a row of big tappable tiles above the filter bar, one per platform you own games for, each showing how many items you've got, color-coded by platform brand. Tap one to filter straight to that system; tap again (or Clear) to go back to everything.
- **Clickable followers/following lists** — the follower/following counts on a profile are now links to a full list of who's actually there, each linking through to their own profile. Same privacy behavior as the counts already had (visible regardless of whether the collection itself is public).
- **Region tags for games** — NTSC-U/C, NTSC-J, PAL, or Region-Free as a field on games, shown on the card and searchable. Requires `region-migration.sql` on existing projects.
- **Physical/Digital tag** — a "Copy" field (Physical or Digital) works on any item type, shows as a badge on the card, and has its own dashboard filter. Requires `copytype-migration.sql` on existing projects.
- **Check eBay price** — a button in the item form looks up current eBay (US) listings for that item and shows the low/average/high asking price, which then shows on the card too. This is *current active listings*, not confirmed sale prices — eBay doesn't offer free public access to sold-listing data anymore, so this is "what it's going for right now" rather than a guaranteed resale value. On-demand only (you click Check, it doesn't run automatically), free with an eBay developer account. A "Refresh all prices" button on the dashboard runs the same check across your whole collection in one go (skipping sold items), with a progress readout and a Stop button since a big collection takes a bit. Requires `ebayprice-migration.sql` on existing projects, plus `EBAY_CLIENT_ID`/`EBAY_CLIENT_SECRET` in `.env.local` (see README).
- **Completeness field for games** — Loose (cart/disc only), CIB (complete in box), or Box only (no manual), as its own field separate from general condition. Feeds directly into the eBay price check too — completeness swings a game's real resale value a lot (a loose cart vs. a CIB copy of the same game can be several times apart in price), so the price lookup now searches with the right term included instead of averaging loose and CIB listings together. Requires `completeness-migration.sql` on existing projects.
- **CSV/spreadsheet import** — an "Import CSV" button on the dashboard bulk-adds items from a spreadsheet instead of one at a time. Includes a downloadable template with the right columns and an example row for every item type. Shows a preview of what's about to be added plus any warnings (unrecognized item type, bad date, etc. — those rows still import with sensible defaults rather than failing outright), then imports in batches with a progress readout.
- **"100% complete" tag** — a checkbox on any item ("all extras/achievements done, a full series or set collected, etc.") beyond the existing play-status/condition fields. Shows as a badge on the card, has its own dashboard filter, and is importable via CSV. Requires `fullycompleted-migration.sql` on existing projects.
- **Collection value over time chart** — a mini chart on the dashboard tracking your estimated collection value (last "Check eBay price" result where you've checked one, purchase price otherwise) across snapshots in time. A snapshot is recorded automatically every time "Refresh all prices" finishes, or manually via a "Record snapshot" button — needs at least two snapshots before a trend line shows up. eBay prices are always USD, so if your display currency isn't USD the total is a mix and only approximate. Requires `valuesnapshots-migration.sql` on existing projects.
- **SEO/discoverability basics** — a real `sitemap.xml` (home, Find Collectors, Leaderboard, and every public profile) and `robots.txt` (keeps the login-gated dashboard and auth pages out of search, points crawlers at the sitemap), a branded social-share preview image that shows up when a link gets posted to Discord/Reddit/iMessage/etc., and proper page titles/descriptions site-wide including per-collector ones on public profiles (e.g. "See Alex's collection — 214 items and counting"). None of this needs anything from you to keep working — it updates itself as people join and make their profiles public.
- **First-time onboarding panel** — a brand-new, empty collection now shows a real welcome panel instead of a bare "No items yet" line: what Shelf Life is, and three clear ways to add a first item (by hand, barcode scan, or CSV import), plus a link to browse other collectors for inspiration. Matters more now that search/shared links might bring in strangers, not just friends who already know how the site works.
- **Fixed silent failures on follow/comment/delete** — found during a pass on loading/error states: following/unfollowing, posting a comment, and deleting an item all failed with zero feedback if something went wrong (and Follow's button could get visually stuck as "Following" even when the database call actually failed). All three now show a small error message (a new toast in the bottom-left corner) instead of quietly doing nothing.
- **Mobile pass: nav, tap targets, toolbar** — the navbar collapses behind a hamburger menu on phones instead of wrapping into 2-3 messy lines; buttons and form fields got a 44px minimum tap height (were as small as ~34px); the dashboard's filter toolbar stacks full-width on narrow screens instead of wrapping into a ragged grid.
- **Consolidated dashboard filters** — the 6 filter dropdowns (Type, Status, Copy, Completeness, Platform, Play status) are now tucked behind a single "Filters" button instead of always taking up a row, with a count badge when any are active and a "Clear all filters" shortcut.
- **Share your shelf** — a "Share my shelf" button on your own public profile. On a phone it opens the native share sheet (Messages, WhatsApp, Mail, etc.); on desktop it copies your profile link to the clipboard.
- **Profile showcase** — a "Manage showcase" button right on your own public profile lets you pin up to 5 favorite items, in whatever order you like, to a dedicated Showcase section at the top — above the full collection grid, styled distinctly (gold border, "Featured" flag) so it stands out, laid out 5 to a row. Requires `showcase-migration.sql` on existing projects.
- **Activity feed** — a new `/feed` page (linked from the navbar as "Feed") shows what the collectors you follow have recently added, finished, or rated — plus a "What's New" sidebar listing recent site updates. Only fires for real moments (a first add, newly completing something, rating for the first time or changing your rating), not every incidental edit, and only for people whose profile is public (same privacy rule as everything else). Requires `activity-migration.sql` on existing projects.
- **Fixed: master set still hid a variant tile you'd actually logged** — root-caused with real debug logging against a live request: TCGdex (the free community database "See master set" is built on) hadn't finished tagging variant data for a set that had only released days earlier, so it reported `reverse: false` for a card that genuinely does have a reverse holo print, even though a real copy of it was already logged. The master set now trusts a print you've actually logged over an unconfirmed "false" from TCGdex — it shows both what TCGdex already knows about *and* whatever you've told Shelf Life directly, instead of only ever trusting TCGdex.
- **Recommended for you** — a panel on the dashboard suggests titles you don't already own, based on what other public collectors who rated the same things highly as you also rated highly (a lightweight "people with similar taste to you" match on shared 4-5 star ratings). Click a recommendation and it opens Add Item pre-filled with the title, type, and cover art. Needs enough shared rating data across the site to surface anything — shows a "not enough data yet" message otherwise. Requires `recommend-games-migration.sql` on existing projects.
- **Steam account integration** — "Log in with Steam" (in Profile Settings) verifies your Steam account, then "Import from Steam" (in the dashboard toolbar, once connected) pulls in your owned PC games automatically as owned/digital items — pick which ones from a checklist, already-imported games are skipped. Requires your Steam profile's "Game details" privacy setting to be Public (Steam has no way to grant per-app access to a private list, login or not). Requires `steam-connect-migration.sql` on existing projects, plus a free `STEAM_API_KEY` (see README).
- **"What should I play next?"** — a widget on the dashboard suggests one thing from your backlog (or wishlist, if nothing's backlogged yet) to play next, weighted toward the genres/platforms you've already rated 4-5 stars. "Try another" re-rolls without repeating the last pick.
- **Xbox/PlayStation trophy & achievement fields** — two new fields on games (a "Platinum'd" checkbox and a completion % field) for tracking your *real* console trophy/achievement progress — kept clearly separate from Shelf Life's own collection-milestone trophy case, both in the field labels and visually. Shows on the card and rolls up into a stats panel (Platinums, average completion, games tracked) on your public profile once you've used it on at least one game. Manual entry only — neither platform has an API this site can use for personal projects. Requires `trophy-completion-migration.sql` on existing projects.
- **Export your collection** — an "Export CSV" button next to Import CSV downloads your whole collection as a spreadsheet at any time, using the same column layout as the import template, so it doubles as a backup you can re-import later if needed.
- **Slimmed down the Play Next and Recommended for you panels** — Play Next now shows a compact thumbnail + title/meta row instead of a full trading-card-style preview; Recommended for you scrolls horizontally in a single row instead of wrapping into multiple rows, so neither panel's height grows out of proportion with the rest of the dashboard.
- **Minimize dashboard panels** — Play Next, Recommended for you, and Collection value over time can each be collapsed down to just their title bar via a "Hide"/"Show" toggle in the header. Remembered per-visitor, so a minimized panel stays minimized next time.
- **Half-star ratings** — personal ratings now go in 0.5 steps (3.5, 4.5, etc.) instead of only whole stars. Click the left half of a star for a half rating. Applies everywhere a rating shows up — item cards, the activity feed, recommendations, "Play next" weighting. Requires `halfstar-ratings-migration.sql` on existing projects.
- **Trophies show up in the activity feed** — landing a Shelf Life trophy now posts to `/feed` for your followers to see, alongside adds/completions/ratings, with a small tier-colored badge (bronze/silver/gold/platinum). Requires `activity-trophies-migration.sql` on existing projects.
- **Leaderboard redesign** — replaced the old 4-column grid of plain text rows with tabs (Trophy case, Biggest collections, Most-owned, Trending — one at a time instead of all cramped together) and a gold/silver/bronze **podium** for the top 3 in each, with cover art or avatars sized up and a colored glow per medal. Also added the **Trophy case** ranking itself: public collectors by Shelf Life trophies earned. (Along the way, fixed two bugs: `supabase-schema.sql` never actually included the trophy case tables, so a brand-new project's trophies silently didn't work until `achievements-migration.sql` was run by hand — folded into the main schema file now; and the page briefly 500'd in production from an event handler on an image that isn't allowed inside a server-rendered page — moved into its own component.) Requires `trophy-leaderboard-migration.sql` on existing projects.
- **Duplicate/near-duplicate warning** — adding (or editing) an item now checks it against your own collection as you type, and shows a soft heads-up ("You might already have this: *Chrono Trigger*") if something with a matching or near-matching title and the same item type is already there. Doesn't block the save — a second platform's copy, or replacing a lost one, are both legitimate reasons to "duplicate" something.
- **Automatic Steam achievement % sync** — a "Sync achievements from Steam" button (in Profile settings, once Steam's connected) walks every Steam-imported game and pulls its real achievement completion % straight from Steam's API, filling in the same Platinum/completion fields that were previously manual-entry-only for console games. Skips games with no achievements or a private profile rather than erroring. Uses the same `STEAM_API_KEY` already set up for Steam import — nothing new to configure.
- **Compare collections** — a "Compare collections" button on another collector's public profile (once you're logged in) opens a side-by-side view: what you both own, what only you own, what only they own, plus a Shelf Life trophy/platinum comparison. Matching uses the same near-duplicate title logic as the add-item warning above, so slightly different title formatting still counts as the same item.
- **Collection tools moved into Profile settings** — Import CSV, Export CSV, Import from Steam, and Sync achievements from Steam moved off the dashboard toolbar and into Profile settings under a new "Collection tools" section, keeping the toolbar itself down to the things you reach for constantly (Refresh all prices, Add Item).
- **Filter/sort by trophy completion %** — a "Highest Trophy Completion %" sort option, plus a filter (Platinum only / 75%+ / 50-74% / under 50% / not tracked yet) for the real Xbox/PlayStation completion field — find what's closest to platinum in your backlog, or see everything you haven't touched yet.
- **10 more Shelf Life trophies** — Window Shopping (10 wishlist items), Renaissance Collector (5 item types), Card Shark (25 trading cards), Crate Digger (10 vinyl records), Curator (fill all 5 showcase slots), Social Butterfly (follow 10 collectors), Popular Shelf (10 comments received), Platform Hopper (10 platforms), Half a Thousand (500 items), and First Platinum (your first real console Platinum tracked) — 28 trophies total now, up from 18. Requires `more-trophies-migration.sql` on existing projects; nothing to backfill by hand, everyone's next trophy check picks up the new ones automatically.
- **Custom lists** — curated sub-lists beyond the 5-item showcase (Favorites, For sale, Currently replaying, or whatever's useful) — create as many as you like from a new "Manage lists" button next to Manage showcase on your own public profile, and any list with items in it shows up on your profile alongside the showcase. Requires `customlists-migration.sql` on existing projects.
- **In-app notifications** — a bell in the navbar for follows, comments on your profile, and new trophies, so those moments don't only exist as an in-the-moment toast you might have missed. Opening the bell marks everything read; the unread count refreshes automatically about once a minute. Requires `notifications-migration.sql` on existing projects.
- **eBay price checks now use your local eBay site** — based on your display currency (Profile settings), GBP searches ebay.co.uk, EUR searches ebay.de, CAD searches ebay.ca, AUD searches ebay.com.au, CHF searches ebay.ch, and everything else still searches ebay.com. Prices shown now use whatever currency symbol that site actually returned, instead of always assuming $. This is a rough proxy based on currency, not a real location lookup — there's no separate country field, so EUR in particular can't tell which Eurozone country you're actually in.
- **Fixed "Collection value" not moving after a price check** — the number at the top of the dashboard only ever used purchase price, so checking an item's eBay price and saving it didn't change the total (even though the value-over-time chart below it already blended the two correctly). Now they're consistent.
- **Smarter eBay searches, and digital items skipped entirely** — price checks for games now also factor in the Condition field (not just Completeness), and "Check eBay price" no longer shows at all for anything marked Digital, since a digital code/download has no eBay resale market. A hint appears if Completeness/Condition are still blank on a physical game, since those two swing the accuracy of the result a lot.
- **"Hide digital items" toggle** — a checkbox in the dashboard's Filters panel that, unlike the existing Physical/Digital dropdown (which resets every visit), stays remembered on your device — for anyone who never wants their digital library cluttering the grid.
- **Fixed stale market values on Digital items** — switching an item's Copy field to Digital hid the price-check button but left a previously-checked value sitting there uncleared. Saving now clears it, since there's no eBay resale market for a digital copy.
- **Fixed mismatched currency symbols between item cards and the collection total** — item cards always showed a hardcoded \$, even after the site started checking prices from other eBay regions; the dashboard total already used your actual display currency, so the two could visibly disagree. Cards now remember and show whichever currency their price was actually checked in. Requires `marketpricecurrency-migration.sql` on existing projects (safe to run — backfills existing prices as USD, since every price checked before this shipped was USD).
- **Digital items no longer count toward Collection value** — the total previously fell back to an item's manually-entered purchase price whenever it had no eBay market price, which still included digital items (only the eBay side was excluded for those). Digital items are now excluded from the total outright, since there's no resale market for them at all.
- **More accurate, less inflated eBay price estimates** — obviously-mismatched listings (lots, bundles, graded/slabbed copies, "bonus disc" bundles) are now filtered out before pricing, and the "typical" figure is a median instead of a plain average, so a couple of outlier listings can't drag a small sample way up. The eBay search itself also got more careful: it now sticks to your currency where possible (falling back to whatever's actually listed, correctly labeled, rather than silently blending currencies together) and no longer appends a Condition word (like "good" or "fair") to the search — those almost never appear verbatim in a real listing title and were quietly zeroing out results for anything without heavy inventory. If the full, more specific search comes up empty, it now automatically retries with just the bare title before giving up.
- **"Refresh all prices" no longer fails silently** — a network hiccup, a genuinely empty result, or a database error used to just skip an item with zero feedback. It now retries once on a failed request, and shows a summary toast when the run finishes (refreshed all, or which items were skipped and why).
- **Consoles** — track physical hardware (Nintendo Switch, PS5, Xbox, retro consoles, etc.) as an eighth collectible type, right alongside games/comics/cards/vinyl/media. Manufacturer, storage/variant, special edition, region, and grade fields (reusing the same underlying columns comics/cards/vinyl already share — no new columns needed), plus Condition/Completeness, tags, barcode scanning, and eBay price checks, all work the same way. Copy (Physical/Digital) doesn't apply — a console is always a physical object you own — so that field is hidden for this type. Requires `consoles-migration.sql` on existing projects.
- **Collection value on public profiles** — a "Collection value" stat now shows on `/u/username` alongside Total items/Owned/Completed, same blend the dashboard already uses. Individual items' market prices already showed on the card itself.
- **Refresh other collectors' prices** — a "Refresh prices" button on someone else's public profile (once you're signed in) re-checks eBay for their whole shelf, the same way "Refresh all prices" works on your own dashboard. Writes through a new `refresh_item_market_price` database function that only ever touches the three market-price columns on a public collection's items — nothing else about someone else's items becomes editable. Requires `publicprice-refresh-migration.sql` on existing projects.
- **Funko Pops** — track figures as a ninth collectible type. Series/line, Pop! #, character, exclusive-to (Hot Topic/SDCC/GameStop/Funko Shop/etc.), grade (PPJoe/GalaxyPop/Raw), and a Chase/special-variant flag — reusing the same underlying columns trading cards already use (card_set/card_number/player_name/publisher/grade/is_variant), no new columns needed. Condition, tags, barcode scanning, and eBay price checks (searching by title + Pop! # for accuracy) all work the same as everywhere else. Copy (Physical/Digital) doesn't apply, same reasoning as consoles. Requires `funko-migration.sql` on existing projects.
- **"Most valuable" leaderboard** — a new leaderboard tab ranks public collectors by estimated collection value, same blend already used on the dashboard/profile (market price where checked, purchase price otherwise). Shown in each collector's own currency — totals aren't converted between currencies, so it's a fair ranking within the same currency but not a precise one across different ones (same known limitation as the rest of the site's currency handling). Requires `valuable-leaderboard-migration.sql` on existing projects.
- **Mobile reorganization: slide-in drawers instead of a stacked page** — the phone nav went from a dropdown that pushed the page down to a proper slide-in side drawer with a dimmed backdrop, same feel as a native app's hamburger menu. On the dashboard specifically, Play Next / Recommended / Value chart — three full panels that used to stack one after another above your collection — now live behind a "Tools & insights" button that opens the same kind of slide-in drawer, so the item grid is the first thing you see under the stats bar instead of the last. The stats bar, item cards, and grid spacing are also tightened up (smaller numbers, tighter card padding, a bit more breathing room per row) so more fits without feeling cramped. None of this touches desktop — it's all scoped to the existing mobile breakpoint.

- **Loan tracker** — mark any owned item as "Loaned to ___" (with a date) so a lent-out book/game/disc doesn't quietly disappear from memory. Shows as a distinctly colored row right at the top of the item's card (never hidden even in the mobile grid's compact view), has its own dashboard filter (Currently on loan / Not on loan), and is included in CSV exports as a backup. Clears automatically if you change an item's ownership away from Owned, or clear the loaned-to name. Requires `loan-tracker-migration.sql` on existing projects.
- **Saved filter views** — a new "Views" button next to Filters on the dashboard lets you save the current search/filters/sort as a named shortcut (e.g. "PS5 backlog," "Comics worth price-checking") and reapply it with one click later, instead of re-picking the same dropdowns every visit. Stored per-device (localStorage), same as the "Hide digital items" preference.
- **Undo on delete** — deleting an item no longer needs a confirm dialog. It disappears immediately, but a "Deleted 'X' — Undo" bar sits in the bottom-right for 6 seconds before it's actually removed from the database, so an accidental click (or a change of mind) is recoverable instead of permanent. Deleting a second item while one is still pending finalizes the first rather than juggling multiple undos.
- **Auto-search for Books and Consoles** — two more collectible types get a "Search" button next to Title, same pattern as games/trading cards. Books search Open Library (free, no signup needed — same source barcode scanning already used, just extended from ISBN-only to a plain title search) and fill in cover, author, and publisher. Consoles match against a built-in list of ~40 common systems (Switch, PlayStation, Xbox, Sega, Atari, Steam Deck, etc.) — there's no good free public console database the way there is for games/books, so this is a curated list rather than a live API, and fills in Manufacturer + Genre (Home console/Handheld) when you pick one. Comics, Vinyl, DVDs, CDs, and Funko Pops still don't have auto-fill — noted in `ROADMAP.md`.
- **Friends-only leaderboard** — a new "Friends" tab on the leaderboard, scoped to just the public collectors you follow — a smaller, more personal "who's ahead" than the site-wide rankings. Built as database views that check who's asking (`auth.uid()`) at query time rather than a fixed list, so results are automatically different (and correctly private) per viewer, including showing empty for a signed-out visitor. Requires `friends-leaderboard-migration.sql` on existing projects.
- **Friends leaderboard: all 5 categories, not just trophies** — the Friends tab now has its own row of category pills (Trophies / Most valuable / Biggest / Most-owned / Trending), same categories as the site-wide leaderboard, all scoped to just your friends. Requires `friends-leaderboard-expanded-migration.sql` on existing projects (on top of `friends-leaderboard-migration.sql`).
- **Next.js upgraded off the vulnerable pinned version** — 14.2.5 → 14.2.35, a patch-only bump within the same minor line (no API changes, nothing to retest behaviorally). Clears the critical/high-severity advisories `npm install` had been warning about (cache poisoning, DoS via Server Actions/Image Optimization, a middleware auth-bypass class of bug, several others) — all fixed upstream by Vercel within 14.2.x, so no need to jump to the breaking Next 16 line to get them. A handful of lower-severity advisories remain (an auth-js path-routing issue, a cookie edge case, postcss) that only resolve via major-version bumps of their own packages — left alone for now rather than bundled into this pass; worth a deliberate look later.
- **Self-service account deletion — built to satisfy Apple's App Store Guideline 5.1.1(v), needs a real live test before you trust it** — a "Danger zone" section at the bottom of Profile settings, gated behind typing your own username to confirm (no accidental single-click delete). The actual deletion happens server-side (`app/api/account/delete`), using only the caller's own verified session — never a client-supplied id, so there's no way to point it at someone else's account. It wipes their Storage files (avatars + item/condition photos, recursively across every item) and then deletes the `auth.users` row via the admin API, which cascades through every table that references `profiles(id) on delete cascade` per `supabase-schema.sql` — comments, follows, achievements, activity, notifications, passkeys, custom lists, everything. **This has not been exercised against a real Supabase project** — this sandbox has no live credentials, and deletion is far too destructive to fake-test against real data anyway. Before trusting this: sign up a disposable test account, add an item, upload an avatar, delete the account, then confirm in the Supabase dashboard that the profile row, its games, and its Storage files are all actually gone. Move to the section above once confirmed working.
- **Storage cleanup on item delete and avatar replace** — deleting an item (single or bulk) now removes its condition photos from the `item-photos` bucket first instead of leaving them orphaned; uploading a new avatar in a different file format now removes the old one instead of leaving it behind (the upload path is keyed by extension, so a .jpg replaced by a .png used to just add a second file rather than overwrite); clicking Remove on your avatar now actually deletes the file instead of only clearing the field. All best-effort — a Storage hiccup here never blocks the delete/upload/remove itself. New shared helper: `lib/itemPhotoCleanup.js`, also used by the existing single-photo remove button in the item form (previously had its own copy of the same logic).
- **"What's new" entries are clickable** — each entry in the feed sidebar now expands in place to show a bit more detail on what actually shipped, instead of just the one-line teaser. New `detail` field on every entry in `lib/whatsNew.js` (still written in plain, visitor-facing language, not `CHANGELOG.md`'s technical detail) and a small client component (`components/WhatsNewList.jsx`) handling the expand/collapse.

**Closed bugs:**
- *App Store rejection, Guideline 4.1(a) Copycats: "screenshots includes references to Pokemon"* — traced to the logged-out home page hero (`app/page.js`), which pulled a real, live-fetched Charizard VMAX card into its trading-card showcase slot via `lib/showcaseCovers.js`'s `fetchPokemonCardCover()`, publisher field literally reading "Pokémon" — the most likely source of the flagged screenshot, since it's the first thing anyone (including a reviewer) sees signed out. That slot now uses fully generic, made-up card details ("Rare Holo," "First Edition," "Trading Card Co.") and fetches no image at all, same as any item with no cover art elsewhere on the site; `fetchPokemonCardCover()` itself was removed as dead code (it also called the old `pokemontcg.io` endpoint, already replaced by TCGdex for the real card-search feature — see the Pokémon auto-fill fix above). Also swapped the one Pokémon-referencing row in the downloadable CSV import template to the same generic details. **This alone doesn't clear the rejection** — Apple reviewed actual screenshot images already uploaded to App Store Connect, which live outside this codebase entirely; see the top of `ROADMAP.md` for what still needs doing there before resubmitting.
- *Collection value chart: min-value label collided with the date row beneath it* — `ValueChart`'s bottom-left "lowest value" label and the "first date" label sat only 8px apart (baseline-to-baseline) on an 11px font, so their glyphs visually overlapped — worse with longer currency-formatted values eating more of that cramped strip. Gave the two rows their own clearly separated bands instead of a single shared padding value.
- *Item cards: long stat labels could push the value off to zero width, and — found on a second pass after the first fix — most cards were truncating far more than they should even at full desktop width* — on the grid's narrower cards, a longer label ("Storage / variant," "Special edition," "Market value," etc.) was locked at `flex: none`, so it never gave up any width — the value next to it got squeezed to 0px and vanished instead of truncating with "…". Fixed that part first (labels wrap onto a second line when they need to, values keep a minimum sliver of width), but a live check afterward showed near-everything with 2+ words was still getting cut off, even in a full-width browser window. Turned out the card grid's `auto-fill` column sizing means a wider window just packs in *more* narrow cards rather than making each one wider — so cards were sitting close to the 180px floor no matter how wide the screen was, leaving very little room for any stat row regardless of the earlier fix. Shortened the wordiest labels ("Storage / variant" → "Storage," "Special edition" → "Edition," "Series / line" → "Series," "Box condition" → "Condition," "Market value" → "Value") to free up space directly, gave the value a bigger guaranteed share of each row (was capping the label at up to 62% of the width, now 50%), and raised the grid's minimum card width from 180px to 200px so there's more room across the board. Ellipsis truncation still happens for genuinely long values (a game owned on four platforms, a long publisher name) — that's expected single-line behavior, not a bug — but the common case no longer clips unnecessarily.

- *Supabase Security Advisor: "Function Search Path Mutable"* on `handle_new_user`, `set_updated_at`, and `recommend_games` — these three didn't pin `search_path` the way the project's other functions already do, leaving them (especially `handle_new_user`, which runs with elevated privileges to create your profile row on signup) theoretically open to a schema-resolution trick. - *Supabase Security Advisor: SECURITY DEFINER functions callable by signed-out visitors* — `award_achievements_for`, `check_and_award_achievements`, `backfill_all_achievements`, and `refresh_item_market_price` were never explicitly locked down, so Postgres's default (EXECUTE granted to everyone, including anon) quietly applied — meaning any of them could technically be called straight from a signed-out browser via the API, bypassing the app entirely. Also found and fixed a real bug while auditing this: `check_and_award_achievements`'s "is this really you" check used `<>` against `auth.uid()`, which silently evaluates to neither-true-nor-false (and gets skipped) when `auth.uid()` is null — i.e. exactly for a signed-out caller — so an anonymous visitor could actually still call it with someone else's user id and force their trophies to recompute. Locked all four down to only the roles that should ever call them, and fixed the comparison to handle nulls correctly. Requires `revoke-internal-function-access-migration.sql` on existing projects.
- *Supabase Security Advisor: same warning on `handle_new_user`* — missed in the first pass since it's a trigger function (can't actually be invoked any other way — Postgres blocks that), but the advisor flags the exposed grant regardless. Revoked. Requires `handle-new-user-revoke-migration.sql` on existing projects.
- *Supabase Security Advisor: previous revoke fix didn't actually clear the warnings* — turns out Supabase grants EXECUTE on every new function directly to `anon`/`authenticated` at creation time, through its own default-privilege setup — a separate mechanism from plain Postgres's generic `PUBLIC` default, which is what the earlier fix revoked. Re-fixed all five functions with an explicit revoke from `anon, authenticated` (not just `public`), and added a project-wide `alter default privileges` so this can't quietly happen again for any function added later. Requires `revoke-anon-authenticated-function-access-migration.sql` on existing projects.
