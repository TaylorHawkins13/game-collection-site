## High priority

- **Cron heartbeat — the one gap the failure-alert emails don't cover** — `lib/cronAlert.js` emails Taylor when a cron job runs and errors, but can't catch a cron that never runs at all (a `vercel.json` config change, a broken build, a Vercel Cron outage — all silence, not an alert). Needs a "last successful run" timestamp per job (a small table each cron upserts on success) plus something outside Vercel entirely watching it — a free dead-man's-switch service like healthchecks.io/Cronitor that expects a periodic ping and alerts if one doesn't show up. The visibility half (the timestamp table + showing it somewhere) is fully buildable now; the true "silence itself gets caught" half needs you to sign up for one of those free services and hand me a ping URL.
- **Account deletion — explicit session revocation on delete** — `supabase.auth.admin.deleteUser()` removes the user for good, but Supabase's JWTs are verified statelessly (signature + expiry, not a live "does this user still exist" check), so it's worth confirming whether a session open on a second device stays technically "authenticated" for up to its token lifetime after deletion, rather than assuming it's cut off instantly. If so, explicitly revoking sessions as part of the delete flow would close that gap.
- **Mobile layout feels disorganized in places** — no single reported page, just a general sense some mobile screens need tidying; worth a fresh pass now that a lot has shipped since the last mobile audit.
- **Accessibility essentials** — the highest-impact subset of the fuller Accessibility list further down: a site-wide `aria-label` audit on icon-only buttons, real `<label for="">`/`id` pairing on form fields, meaningful `alt` text on cover art/avatars/trophy icons, `aria-live` regions for toasts and import progress, a skip-to-content link, and confirming the browser's default focus outline is visible everywhere. Matters for real users, and for eventually turning the App Store's Accessibility Nutrition Label answers from "not verified yet" into real, tested ones.
- **SEO landing pages for specific searches** — dedicated pages targeting terms like "video game collection tracker," "comic collection app," "collectible database," "retro game inventory." Cheap, compounds over time, builds on the sitemap/metadata work already shipped. (From the outside review Taylor got — 8/10, generally positive.)

## Medium priority

- **Affiliate "buy it" links on wishlist items** — link a wishlist item's "Check eBay price" result to a real eBay Partner Network or Amazon Associates affiliate link, so an actual purchase earns a small commission. No ad-network policy issues (it's just a link), works identically on web and in the app.
- **Shareable public wishlist / gift-list link** — a lightweight link, separate from the full profile, listing just a wishlist — meant for sending to family/friends around birthdays or holidays. Pairs well with the affiliate-link idea above.
- **Collection appraisal / insurance-ready PDF export** — a polished, presentation-style export (itemized, current market values, totals), distinct from the existing raw CSV export — useful for insuring a valuable collection.
- **"On this day" collection memories** — surfaces what you added on this date in a previous year, from activity data already being recorded. Small build, nice recurring reason to open the app.
- **Full physical-release catalogue per console** — pick a platform (e.g. "PlayStation 2"), see every game ever released for it, greyed out except what's logged. IGDB has the per-platform list, but it's thousands of entries for any major system, so this needs real pagination/search within the view itself.
- **Full canonical catalogue per TCG set** — same idea for trading cards: pick a set, see every card actually in it. Scryfall (Magic) and TCGdex (Pokémon) both expose real per-set card lists, so this can be a genuine complete list rather than only what's already been logged by someone.
- **Extend "See full series" to every remaining collectible type** — currently games, comics, trading cards, and Funko Pops only; Vinyl, CDs, DVDs, VHS, Books, and Consoles have none. No natural numbered-series field for these, so "series" needs its own per-type definition (likely grouping by artist/director/author).
- **Rest of the Accessibility checklist** — contrast audit (WCAG AA), differentiating status without color alone, keyboard support for the star rating, confirming pinch-to-zoom isn't disabled, a manual text-size control, respecting `prefers-reduced-motion`, a longer/extendable undo window, a public `/accessibility` page, and a full keyboard tab-order check across the dashboard grid/leaderboard/search. See "Accessibility (full list)" below for the complete, organized version.
- **Automated tests** — there currently aren't any; worth adding once the feature set stabilizes so future changes don't need this much manual click-testing.
- **Image handling for cover art** — cover URLs are trusted as-is right now; downloading and re-hosting them (or at least validating them) would be more robust than relying on external links staying alive.

## Later (bigger, more design work)

- **Shared/household collections** — let a second account co-manage one collection. Real permission/ownership questions to work through, not a quick add.
- **Multi-language support (i18n)** — everything's English-only, fine for a friends-and-family project but a real ceiling for an actual App Store product. Worth it once there's a specific market to justify it.
- **AI shelf-photo bulk import** — one photo of a physical shelf, detect and suggest multiple items at once instead of scanning barcodes one at a time. The most speculative idea here — accuracy on a photo full of spines needs real testing before promising it works.
- **Import from Goodreads / Discogs** — same idea as the existing Steam import, for Books and Vinyl/CDs respectively.
- **Per-item reviews (separate from personal rating)** — a review system letting other users read what people think of a specific item, aggregated site-wide.
- **Wantlist matching / trading** — surface when someone you follow has something on your wishlist, or a duplicate they might trade.
- **Notification digest emails** — an opt-in weekly summary of your own stats or followed collectors' activity.
- **Live currency conversion** — currency is display-only right now; real conversion needs a rates API (the leaderboard-ranking one already added is a start) and a decision on the "true" underlying value across currencies.
- **Xbox / PlayStation account integration** — Steam is done. Xbox is gated behind app registration; PlayStation has no official public API at all (reverse-engineered access only, fragile and ToS-gray-area).
- **Global chat** — a site-wide message board, separate from per-profile comment walls. Needs real-time updates and real moderation once it's not just friends talking.
- **More Shelf Life milestone variety** — platform-completionist badges, genre/decade-spanning badges, room for oddball community-suggested ones beyond "own N items."
- **Even more collectible types** — board games, action figures/toys, coins, whenever there's demand.
- **iPad-specific polish** — the app went in as a Universal build (phone layout scaled up); a real iPad layout would be a nice follow-up if iPad usage turns out meaningful.
- **Native ad revenue from the app itself (AdMob)** — even with AdSense on for the website, the app earns $0 on its own; real native integration (AdMob SDK or Google's WebView Ads API) needs genuine Swift/native work. Not worth it at current traffic.

## Accessibility (full list)

The modal/dropdown pass (keyboard operability, focus trapping, `role="dialog"`) covered what was flatly unusable without a mouse. The highest-impact items from this list were promoted to High priority above; this is the complete set for reference.

**Screen readers (VoiceOver / TalkBack)** — site-wide `aria-label` audit on icon-only buttons; `aria-live` regions for toasts/import progress/trophy popups; real `<label for="">`/`id` pairing on every form field; meaningful `alt` text on every image; a text-based "view as a list" alternative for the shelf mosaic; proper landmark regions (`<nav>`/`<main>`/`<aside>`) and a clean, non-skipping heading hierarchy.

**Keyboard-only navigation** — a skip-to-content link; real keyboard support for the star rating (arrow keys + Enter/Space); confirming the browser's default focus outline is never suppressed without a replacement; a full tab-order check across the dashboard grid, leaderboard, and search results.

**Low vision / visual** — a WCAG AA contrast audit (`.sub` muted text, badge/pill combos, both themes); differentiating status without relying on color alone (ownership badges, podium medals, trophy tiers); confirming pinch-to-zoom is never disabled; a manual text-size control in Settings (iOS's system "Larger Text" doesn't reach web content inside the wrapped app).

**Motion** — respecting `prefers-reduced-motion` for modal fades, toast slide-ins, hover effects, and the trophy-earned popup.

**Other** — a longer or pause/extendable undo window (currently a flat 6 seconds); a public `/accessibility` page matching the existing `/privacy`/`/feedback` pattern, and the kind of thing that helps if the App Store's Accessibility Nutrition Label answers ever need revisiting with real, tested claims instead of "not verified yet."
