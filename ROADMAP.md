## High priority

- **Mobile layout feels disorganized in places** — no single reported page, just a general sense some mobile screens need tidying; worth a fresh pass now that a lot has shipped since the last mobile audit.
- **Widened `games` RLS policy for `wishlist_public` technically permits wishlist rows through *any* games query, not just the gift list page** — noticed while building it (see `CHANGELOG.md`): the policy change is scoped to `ownership = 'wishlist'` rows only, and both existing views that query another user's `games` (`/compare/[username]`, the shelf mosaic) were checked and are safe — both already gate on `is_public` at the app level before ever running the query, so nothing leaks today. But any *future* feature that queries `games` for a non-owner without an explicit `is_public` check would now silently see that profile's wishlist items even when the profile is otherwise private. Worth keeping in mind rather than a build item on its own — flagging so it isn't a surprise later.
- **Worth watching: crowdsourced series matching now fetches every row of the item type, not just matches** — noticed while adding normalization to `lib/seriesCrowdsource.js` (see `CHANGELOG.md`): merging near-duplicate series names (punctuation/spacing differences) properly means comparing normalized text in JS, which can't be done as a server-side exact match — so it now pulls every row of that `item_type` and filters client-side instead of letting Postgres narrow it down first. Fine at today's scale (Funko Pops only, RLS-scoped to public profiles plus the viewer's own), but would need a real search index if this ever handled a type with meaningfully more rows.
- **Worth watching: `/api/igdb-franchise`'s `maxDuration = 20` may not actually cover its own worst case** — noticed while sweeping the remaining missing-timeout routes (see `CHANGELOG.md`): every other route in that sweep fires at most one or two sequential fetches, so an 8-second-per-fetch timeout plus a 20-second route ceiling comfortably covers the worst case. `lib/igdbSearch.js`'s `getFranchiseGames()` is the exception — a full request can chain up to four sequential legs (the initial search, the franchise-count check, the franchise's games, then the collections' games), each individually capped at 8 seconds but not capped as a whole, so a genuinely unlucky request (several slow legs in a row) could still exceed the 20-second backstop and hit Vercel's own limit. Not a live report, just a gap noticed by inspection — worth either raising `maxDuration` further (cost/plan-limit tradeoff, not mine to decide) or restructuring the franchise and collection fetches to run concurrently instead of sequentially.
- **Worth watching: bulk actions never say how many selected items were silently skipped, only how many succeeded** — noticed while adding the gift-priority bulk action (see `CHANGELOG.md`): both it and the existing platform bulk-action apply only to the subset of a selection that's actually eligible (wishlist-only, platform-having-types-only) and show one all-or-nothing toast either way — "None of the selected items..." if zero qualify, or a plain success count if at least one does, with no "applied to 4, skipped 2" breakdown when a selection is a genuine mix. Fine today since it's simple to reason about after the fact, but worth a real "X applied, Y skipped (reason)" message if selections mixing eligible and ineligible items turn out to be a common, confusing case rather than a rare one.
- **Worth watching: the CSV price-drop-alert-threshold column carries no currency of its own** — noticed while wiring it into CSV export/import (see `CHANGELOG.md`): the column is a bare number, always interpreted in the collector's own display currency (same as the in-app field), which is invisible to anyone editing the raw CSV in a spreadsheet — reasonable for a personal backup/re-import round-trip, but if someone ever authors a CSV by hand or shares one, a `25` in that column means something different depending on whose profile it lands on. Same root cause as the already-documented "eBay prices are always USD" limitation elsewhere in the app, not something this round of work made any better or worse — just newly visible while touching the field.

## Medium priority

- **Affiliate "buy it" links on wishlist items** — link a wishlist item's "Check eBay price" result to a real eBay Partner Network or Amazon Associates affiliate link, so an actual purchase earns a small commission. No ad-network policy issues (it's just a link), works identically on web and in the app. Pairs well with the gift list link below — a family member with an affiliate-tagged buy link right on the item they're looking at is a much shorter path to an actual purchase.
- **Collection appraisal / insurance-ready PDF export** — a polished, presentation-style export (itemized, current market values, totals), distinct from the existing raw CSV export — useful for insuring a valuable collection.
- **Full physical-release catalogue per console** — pick a platform (e.g. "PlayStation 2"), see every game ever released for it, greyed out except what's logged. IGDB has the per-platform list, but it's thousands of entries for any major system, so this needs real pagination/search within the view itself.
- **Magic master sets** — the Pokémon side of this shipped (see `CHANGELOG.md`: "See master set," a real per-set, per-variant TCGdex checklist replacing the old crowdsourced trading-card series view). Magic falls back to the crowdsourced-from-Shelf-Life's-own-data version now (see `CHANGELOG.md` — it was actually silently routed to the Pokémon-only TCGdex endpoint and getting nothing at all until that fix). Scryfall has clean, free per-set card data (already used for Magic search) including variant/frame info, so the same approach TCGdex got should carry over as a real Magic-specific backend — just needs its own pass since Scryfall's data shapes (and what counts as a "variant" — foil, borderless, showcase, etc.) aren't identical to TCGdex's.
- **Pokémon master sets: show variants you don't own yet, not just confirm the ones you do** — the shipped version only expands a card into its real Normal/Reverse/Holo/1st Edition tiles once you've already logged a variant copy of it (deliberate — fetching real variant data for every card in a 100-250+ card set on every click risks a timeout and hammers TCGdex's free API). A precomputed/cached version of each set's full variant breakdown (refreshed periodically rather than fetched live per click) would close the gap and let the grid show "you're missing the reverse holo of this" for cards you've never touched, which is closer to what a completionist actually wants from a master-set tracker.
- **Extend "See full series" to every remaining collectible type** — currently games, comics, trading cards, and Funko Pops only; Vinyl, CDs, DVDs, VHS, Books, and Consoles have none. No natural numbered-series field for these, so "series" needs its own per-type definition (likely grouping by artist/director/author).
- **Rest of the Accessibility checklist** — contrast audit (WCAG AA), differentiating status without color alone, keyboard support for the star rating, confirming pinch-to-zoom isn't disabled, a manual text-size control, respecting `prefers-reduced-motion`, a longer/extendable undo window, a public `/accessibility` page, and a full keyboard tab-order check across the dashboard grid/leaderboard/search. See "Accessibility (full list)" below for the complete, organized version.
- **Automated tests** — there currently aren't any; worth adding once the feature set stabilizes so future changes don't need this much manual click-testing.
- **Image handling for cover art** — cover URLs are trusted as-is right now; downloading and re-hosting them (or at least validating them) would be more robust than relying on external links staying alive.
- **Yearly "Wrapped"-style recap** — a shareable end-of-year summary (items added, most active month, biggest completion, estimated value change) built from data already being tracked (the activity feed, value snapshots). Small build for what it gives back — the kind of thing people actually screenshot and share, the way Spotify Wrapped does every December.
- **Suggest people to follow, not just items to add** — "Recommended for you" already surfaces items based on shared 4-5-star ratings with other public collectors; the same signal could surface *collectors* worth following instead of just items worth owning, on the Find Collectors page or the dashboard.
- **"For sale" flag on owned items, shown on your profile** — distinct from the wishlist-only gift list: a lightweight toggle + asking price on an item you already own, shown on your public profile (similar spirit to Showcase highlighting favorites) so someone browsing your collection can see what's actually available without you setting up a listing anywhere else. A natural, much smaller first step toward the in-app marketplace idea below, buildable well before that is.
- **Population data for graded items** — trading cards/comics already have a Grade field; for a graded item, pulling the population count for that specific grade from PSA's or CGC's public lookup tools (where available) would show how rare that exact grade actually is, right alongside the grade itself.
- **Opt-in automatic backup of exports** — "Download my data" and "Export CSV" already exist but are manual, on-demand; a periodic export emailed automatically (or pushed to Drive/Dropbox) would matter more once someone's tracking a genuinely valuable collection and wants an off-site backup without remembering to click Export.
- **Chat-style quick add** ("logged a Chrono Quest for $40 today") — parse a short typed sentence into a pre-filled Add form instead of picking fields one at a time, for fast bulk logging right after a store run. Speculative, same caveat as AI shelf-photo import below — needs real testing on parse accuracy before promising it works.

**The three below (plus two more, in "Later" further down) came out of an actual competitor pass (Aug 2026) — Discogs, CLZ/Collectorz, iCollect Everything, Collectr, TCGplayer, League of Comic Geeks, Backloggd, and Grouvee. Full comparison shared in chat; short version: nobody else covers this much breadth *and* real social features *and* real per-type completion data at once, but a few of them each have one specific thing worth borrowing.**

- **Public, browsable community lists** — Backloggd and Grouvee both lean hard on "browse thousands of community-made lists" as a discovery surface and a real reason to come back; Shelf Life's custom lists already exist (Favorites, For sale, etc.) but are only ever visible on their owner's own profile, nowhere to browse across everyone. A `/lists`-style directory of public lists (same `is_public`/RLS pattern everything else already uses) would turn a feature that's already built into an actual competitive edge instead of a private convenience.
- **Aggregate community rating shown per item** — Backloggd shows a crowd rating built from millions of individual ratings on every game page. Shelf Life's own personal ratings already feed "Recommended for you" behind the scenes, but nothing ever surfaces a title's *aggregate* rating anywhere — not the collectible detail page, not the SEO landing pages. A simple average-of-all-public-ratings stat would give visitors exactly the social-proof signal rival community sites are built around.
- **Single-item AI photo auto-fill** — iCollect Everything's standout feature, and a much smaller, more provably-accurate slice of the "AI shelf-photo bulk import" idea already below: point the camera at one item, get title/cover/details auto-filled, instead of a whole shelf at once. Worth doing this first and learning from real accuracy before attempting the harder multi-item version.

## Later (bigger, more design work)

- **Shared/household collections** — let a second account co-manage one collection. Real permission/ownership questions to work through, not a quick add.
- **Multi-language support (i18n)** — everything's English-only, fine for a friends-and-family project but a real ceiling for an actual App Store product. Worth it once there's a specific market to justify it.
- **AI shelf-photo bulk import** — one photo of a physical shelf, detect and suggest multiple items at once instead of scanning barcodes one at a time. The most speculative idea here — accuracy on a photo full of spines needs real testing before promising it works.
- **Import from Goodreads / Discogs** — same idea as the existing Steam import, for Books and Vinyl/CDs respectively.
- **Per-item reviews (separate from personal rating)** — a review system letting other users read what people think of a specific item, aggregated site-wide.
- **Wantlist matching / trading** — surface when someone you follow has something on your wishlist, or a duplicate they might trade.
- **Notification digest emails** — an opt-in weekly summary of your own stats or followed collectors' activity.
- **Live currency conversion** — currency is display-only right now; real conversion needs a rates API (the leaderboard-ranking one already added is a start) and a decision on the "true" underlying value across currencies.
- **Xbox / PlayStation account integration** — Steam is done. Xbox is gated behind app registration; PlayStation has no official public API at all (reverse-engineered access only, fragile and ToS-gray-area).
- **Global chat** — a site-wide message board, separate from per-profile comment walls. Needs real-time updates and real moderation once it's not just friends talking.
- **More Shelf Life milestone variety** — platform-completionist badges, genre/decade-spanning badges, room for oddball community-suggested ones beyond "own N items."
- **Even more collectible types** — board games, action figures/toys, coins, whenever there's demand.
- **iPad-specific polish** — the app went in as a Universal build (phone layout scaled up); a real iPad layout would be a nice follow-up if iPad usage turns out meaningful.
- **Native ad revenue from the app itself (AdMob)** — even with AdSense on for the website, the app earns $0 on its own; real native integration (AdMob SDK or Google's WebView Ads API) needs genuine Swift/native work. Not worth it at current traffic.
- **Public read-only API / personal access tokens** — let a collector generate an API key scoped to just their own data, so anyone who wants their collection in a spreadsheet, a personal dashboard, or a script can pull it directly instead of exporting CSVs by hand. Real design work either way: token issuance/revocation UI, rate limiting, and deciding what's actually worth exposing (probably a read-only mirror of what's already visible via the existing RLS rules, nothing new).
- **In-app marketplace: sell to another collector directly, not just an affiliate redirect** — distinct from the affiliate "buy it" links and the "For sale" flag above (medium priority — see those two): those point outward or just show interest, this would be an actual listing another collector could act on inside Shelf Life. Real trust, payment, and dispute questions come with that — easily the biggest-scope item on this list. Worth starting with "list for sale + a way to message the seller" long before anything resembling in-app payments.
- **Native home-screen widgets (iOS/Android)** — today's stats, Play Next, or trophy progress right on the home screen, now that the app is wrapped for both platforms. Needs genuine native work (WidgetKit on iOS, App Widgets on Android) — same caveat as AdMob above, not buildable from this codebase alone.
- **Browser extension: add an item while shopping** — a small "Add to Shelf Life" extension that captures a title/price/image straight off an eBay/Amazon/retailer listing page instead of typing it in from memory later. A genuinely new platform surface — its own codebase, its own store listing and review process (Chrome Web Store this time, not Apple's or Google's).
- **Printable QR/barcode labels per item** — a small sticker linking straight back to an item's Shelf Life entry, for anyone who actually boxes up and stores a physical collection and wants a fast way to look a boxed item back up. Needs real label-sheet layout work (Avery-style templates) to be genuinely useful rather than a novelty.
- **Community-verified master sets** — master-set data currently comes entirely from TCGdex/Comic Vine/IGDB, or Shelf Life's own crowdsourced logs; a "flag this as wrong" or trusted-contributor correction layer would start to matter once master sets cover enough collectible types that data errors actually show up. Same flavor of real moderation/trust question as Global chat above.
- **Pull list / upcoming-release calendar with spend forecasting** — from the Aug 2026 competitor pass (see note above): League of Comic Geeks' single most-loved feature is exactly this — a calendar of what's coming for the things you already track, plus a running "here's what you'll owe this week/month" total. IGDB (games) and Comic Vine (comics) both already expose future release dates to this codebase for other features, so the data itself is reachable; the real work is a calendar UI and getting the spend-forecast math right across two very different collectible types at once.
- **Real sold-price data, not just current listings** — same competitor pass: Collectr and TCGplayer both lean on actual transaction/sold-price data as their credibility anchor for "what's this actually worth." Shelf Life's own eBay price check is explicitly current active-listing prices, not sold comps (a known, already-documented limitation — see `CHANGELOG.md`), because eBay stopped offering free access to sold-listing data. Flagging honestly rather than pretending it's a clean build: closing this gap for real needs either a paid market-data source or something against eBay's ToS, so it's more of an "if the budget ever supports it" item than a normal build.

## Accessibility (full list)

The modal/dropdown pass (keyboard operability, focus trapping, `role="dialog"`) covered what was flatly unusable without a mouse. The highest-impact items from this list were promoted to High priority above; this is the complete set for reference.

**Screen readers (VoiceOver / TalkBack)** — ~~site-wide `aria-label` audit on icon-only buttons~~, ~~`aria-live` regions for toasts~~ (done — toasts, and CSV/Steam-import progress readouts specifically), ~~real `<label for="">`/`id` pairing on every form field~~, and ~~meaningful `alt` text on cover art/avatars~~ are done (see `CHANGELOG.md`). Still open: `TrophyToastListener`'s trophy-earned popup has no `role`/`aria-live` (unlike the regular toast system, which does); a text-based "view as a list" alternative for the shelf mosaic; proper landmark regions (`<nav>`/`<main>`/`<aside>`) and a clean, non-skipping heading hierarchy.

**Keyboard-only navigation** — ~~a skip-to-content link~~ (done); real keyboard support for the star rating (arrow keys + Enter/Space); ~~confirming the browser's default focus outline is never suppressed without a replacement~~ (audited — the one real gap found, `.chip-input`, is fixed; `.mosaic-tile`'s `outline: none` already had a proper `:focus-visible` replacement); a full tab-order check across the dashboard grid, leaderboard, and search results.

**Low vision / visual** — a WCAG AA contrast audit (`.sub` muted text, badge/pill combos, both themes); differentiating status without relying on color alone (ownership badges, podium medals, trophy tiers); confirming pinch-to-zoom is never disabled; a manual text-size control in Settings (iOS's system "Larger Text" doesn't reach web content inside the wrapped app).

**Motion** — respecting `prefers-reduced-motion` for modal fades, toast slide-ins, hover effects, and the trophy-earned popup.

**Other** — a longer or pause/extendable undo window (currently a flat 6 seconds); a public `/accessibility` page matching the existing `/privacy`/`/feedback` pattern, and the kind of thing that helps if the App Store's Accessibility Nutrition Label answers ever need revisiting with real, tested claims instead of "not verified yet."
